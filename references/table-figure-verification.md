# Verify existing tables and graphs

Use this reference for capability 1 when tables or figures are in scope.
Keep the five-step order in `analysis-integrity.md`: inventory and plan
before running, execute the author's existing pipeline, then compare.

## Scope and gates

Resolve manuscript table includes and figure references to the actual files
used in its build. Record submitted artifact paths and hashes. Do not check
an old draft or only the graph freshly regenerated by the pipeline. When
competing scripts/data/artifacts could govern, ask which is canonical.

The usual code/data/shell gates apply. Figure verification additionally
needs access to the submitted artifact: use image reading for raster images
or rendered PDFs when available, plus exact vector/plot data when present.
Without a usable inspection surface, mark the affected rendering checks
unverifiable and continue independent numerical checks. A sidecar file alone
does not prove the displayed graph uses its values.

Preserve originals and redirect **all** pipeline writes into the proposal
directory or use the safe disposable-copy procedure. Do not run an existing
plot script in place if it overwrites the submitted graph. Verification
does not author a replacement analysis or plotting script.

## Tables

1. Inventory every in-scope cell by table, row/column labels, statistic,
   unit, sample, precision, and footnote. Keep repeated occurrences separate.
2. Trace cells to the producing command and output field. Match by labels
   and definitions, not row position; a coefficient, standard error, and
   confidence limit are different quantities.
3. Execute the planned pipeline. Compare the submitted cells using the
   existing unit, rounding, bound and boundary-tie rules. Include reported
   counts, totals, and intervals. Missing output fields remain unverifiable.
4. Check labels, units, footnotes and captions against the traced outputs.
   A correct number under the wrong group's heading is a discrepancy even
   when the numerical value alone matches.

## Graphs

1. Inventory every panel/series: axes, units, category/legend mapping,
   sample, transformations, statistic, error-bar definition, numeric labels,
   and caption. Ordinary ticks are axis metadata, not separate findings.
2. Execute the author's producing pipeline. Obtain the values actually
   supplied to the plotting step, including identities, coordinates, counts
   and uncertainty. Trace through existing code/output; do not substitute
   a newly chosen fit or statistic. Log the producing command and inputs.
3. Compare these values with the **submitted graph**. Prefer exact labels,
   vector coordinates with the documented axis transform, or original
   plotting-object data. Log the extraction/inspection method and mapping.
   Execute and log any coordinate-to-value extraction command; a handwritten
   side calculation is not verified substance under the master rule.
   Check marks separately from labels: a wrong label with a correct bar
   and a wrong bar with a correct label are distinct failures.
4. Inspect the rendering for axes/scales, units, series/category identity,
   omitted/duplicated data, clipping, error bars and caption consistency.
   A log axis or nonzero origin is not automatically an error; flag a
   conflict with the stated quantity, undisclosed transformation or scope.
5. Never estimate exact values by eye or infer numerical results from
   pixels. For unlabeled raster marks with no accessible exact encoding,
   their numerical parity is unverifiable. A rerender can aid inspection,
   but visual resemblance alone cannot earn an exact match. Confirming
   printed labels does not confirm uninspected geometry.

Propose corrections without editing any artifact. A requested redesign uses
capability 2; a new transformation or statistic uses capability 3.

## Report

Use the four existing sections. Under Results, give each checked aspect a
match, mismatch, or unverifiable finding with evidence. Distinguish numeric
parity from structural/rendering checks. Never declare a whole table/graph
verified when only some cells, labels or input data were checked. Raise
discrepancies and access limitations in Author decisions.

Keep JSON schema `facts-and-figures.verification/1`. In `values`, record
numeric cells, figure labels, and exactly recoverable marks at precise
locations such as `manuscript.md, Table 1, row B, column Mean` or
`figures/quality.svg, Figure 1, series B, bar`. Use the literal reported
text/encoding; record extraction/axis mapping in `note`, and the executed
pipeline's full-precision value in `computed`. If no exact reported value
is accessible, use a descriptive `reported` string, classify unverifiable,
set `computed` null and give the reason. Non-numeric legend/axis/caption
findings belong in prose and relevant numeric notes; do not invent numbers
for them. Numeric verdicts must agree between prose and JSON. All shared
provenance, preservation, output-location and cleanup requirements apply.
