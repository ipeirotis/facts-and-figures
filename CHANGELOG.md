# Changelog

All notable changes to facts-and-figures (called paper-analyst before v0.2.0) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/). Versions use [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

Codex review findings on the skill as vendored into a manuscript repository (IliasTriant/inattentiveness_paper#14), each checked against the current text before fixing:

- A verification pipeline that writes to the working tree no longer runs there after the author approves. `references/analysis-integrity.md` step 4 said to stop and ask, which implied approval licensed an in-place run, while the integrity norms say verification writes nothing of the author's. The run now goes, in order, to a read-only or dry-run path, an output location redirected into the proposal directory, or a disposable copy there (`git archive` or `git clone`, never `git worktree add`, which writes into the author's `.git`) removed at teardown; with none possible, its values are unverifiable. The integrity norm names these as the only additions verification may author.
- The rounding tolerance follows the last displayed digit, exponent included. `u = 10^-k` read `1.2 × 10^-4` as one decimal and accepted values orders of magnitude off; scientific notation now uses `u = 10^(e-k)`.
- A BigQuery time-travel decorator no longer counts as a pinned data version by itself (`references/compute-environment.md`). It resolves only within the two-to-seven-day time-travel window, so the point it fixes must be preserved durably, as a table snapshot (with the author's go-ahead) or an archived export with its hash, or the result is unverifiable. A partition key with a fixed as-of date is no longer listed as a pin either, since an ordinary partition can be rewritten; it is preserved the same way unless the source guarantees immutability.
- The rounding test runs in the manuscript's display unit. A reported `7%` against a computed `0.071` was a false mismatch (`m = 7`, `v = 0.071`); `v` is now converted into the displayed unit (percent, basis points, millions) before the interval applies, the conversion is logged, and an unstated unit is a question for the author.
- The run marker is created exclusively (`SKILL.md`). Two runs in one checkout could both rewrite it and share `verification-report.json`, and the first teardown removed the other's guard; an existing marker now stops the run with a reported conflict, and a run never removes a marker it did not create.
- `data_versions` accepts remote inputs (`references/verification-report.md`). Keys were restricted to repository-relative paths, so a warehouse or bucket read could not record what it actually read; a remote input is now keyed by its canonical identifier with the pin (`bq://…`, `gs://…#generation`), never by the config file naming it.
- The README's CI gate rejects non-finite values. `json.load` accepts `NaN` and `Infinity`, which passed the numeric check, so a pipeline failure yielding `NaN` could be recorded as a match and pass the gate; the check now requires floats to be finite (`math.isfinite`), while ints pass as they are, since converting a very large one would overflow.
- The write-boundary hook refuses a run marker under a non-root working directory (`hooks/write-boundary.sh`). With no marker armed, a session whose cwd sat in a subdirectory could create `facts-and-figures-out/.active` there; once the cwd returned to the repository root the ancestor scan no longer found it and the guard went inert for the rest of the run. Raised in Codex review of the hook vendored into IliasTriant/inattentiveness_paper#14; The same check applies to the parallel-mode bootstrap of a second checkout. A candidate with no enclosing root (a non-git checkout reached only through the cwd) keeps its candidacy. `evals/test_hook.py` covers the subdirectory denial and the root bootstrap from a subdirectory cwd, for a single checkout and for a second one.

- An endpoint tie is classified by the stated convention: the included lower endpoint is a match and the excluded upper endpoint a mismatch, both still named as boundary cases. The tie paragraph had said to report any endpoint hit as a match, which certified an upper-endpoint value the manuscript does not display.
- A redirected output location counts as non-mutating only when every write the pipeline makes goes there (caches, logs, side tables), not just its main output; otherwise the disposable copy runs.
- The subagent wrapper and README state that `omitClaudeMd` needs Claude Code v2.1.271 or later; on older versions the field is ignored, and the wrapper's rule to treat those files as read-only input applies to what loaded.
- The README's CI gate checks field types, not truthiness: `location`, `reported`, `tolerance`, `producing_command`, and `reason` must be non-empty strings, and `classification` one of the three classes.

- Scientific notation at the bottom of a decade gets an asymmetric interval: a mantissa of exactly 1 takes its lower endpoint from the decade below (`|m| - u/20`), so `1.0 × 10^3` accepts `[995, 1050)` and no longer certifies `960`, which displays as `9.6 × 10^2`.
- The disposable copy is used only after confirming that every write resolves inside the copy or the proposal directory; an absolute output path, an environment-configured cache path, or a copied symlink can lead a copy's writes back into the author's checkout.

## [0.5.0] - 2026-10-07

Completes the roadmap's items 4 and 5: the repository is now a Claude Code plugin, and verification is scriptable end to end. Minor bump: the output contract gains the machine-readable companion.

### Added

- Plugin packaging. The repository root is the plugin root — a single-skill plugin keeps `SKILL.md` in place, so the plain-skill install path is untouched and nothing is duplicated. `.claude-plugin/plugin.json` (version-pinned, agent path named explicitly), `.claude-plugin/marketplace.json` (the repo is its own marketplace), and `hooks/hooks.json` (registers the write-boundary guard via `${CLAUDE_PLUGIN_ROOT}`). One install activates skill, subagent, and hook: `/plugin marketplace add ipeirotis/facts-and-figures` then `/plugin install facts-and-figures@facts-and-figures`. `claude plugin validate . --strict` passes and CI runs it on every push.
- The machine-readable verification report. Verification writes `verification-report.json` into the proposal directory whenever the session can write — one record per manuscript value carrying `location`, `reported`, `classification`, `computed`, `tolerance`, `boundary`, and `producing_command` (or `reason` when unverifiable). `references/verification-report.md` owns the schema and its field rules; `SKILL.md`'s Return section carries the mandate. The JSON is substance under the master rule, must agree with the prose report, and stays in the proposal directory — the run marker is torn down, the report is kept.
- `evals/grade_json_report.py`, exact grading over the JSON companion: schema and required fields, classification equality, boundary flags, computed values against the documented true values (percent targets accepted in either unit), producing commands present, and no computed value asserted for unverifiable targets. `run_agent_eval.sh` grades both layers and fails if the companion is missing from a writable workspace.
- `evals/test_graders.py` and `evals/tests/`: deterministic grader self-tests (good, bad, and gate mock reports for both graders) so a grader regression is caught without an API key.
- CI workflows. `ci.yml`: fixture self-check, grader self-tests, dangling-reference check, three-way version consistency (`VERSION`, `SKILL.md`, `plugin.json`), and strict plugin validation on every push and pull request. `agent-eval.yml`: the full headless eval against the fixture on pushes to `main` touching runtime files, gated on the `ANTHROPIC_API_KEY` secret with a clean skip when absent, reports uploaded as artifacts.
- A template workflow in `README.md` for verifying a real paper repository on every push, with the policy note that failing on `unverifiable` is the author's choice, not a default.

### Fixed

Review findings on the pull request, each verified before fixing:

- The write-boundary hook parses its payload straight from stdin instead of exporting it: a `Write` payload carries the whole file content, and the environment-variable route failed with `E2BIG` at roughly 128 KiB — failing open, since a hook error with empty output does not block. It also no longer allows a scratch root that contains the project: a checkout living under `/tmp` (as the eval workspaces do) was previously whitelisted entirely while the marker was armed. `evals/test_hook.py` covers both regressions plus the ordinary allow and deny paths, and runs in CI.
- The subagent wrapper's tool list includes `Skill` and preloads the `facts-and-figures` skill, so a plugin-installed subagent can actually reach the protocol; the on-disk fallback paths remain for plain installs.
- `SKILL.md` places the run marker inside the proposal directory the author named rather than hard-coding the default, keeping the marker and the hook pointed at the same directory.
- `README.md` qualifies parallel fan-out: concurrent runs need per-run proposal directories (`FACTS_AND_FIGURES_OUT`) or separate checkouts, since the default directory would share one marker and one `verification-report.json`.
- The answer key gains the two pipeline-backed counts the manuscript also reports — the 40-worker sample size and the 10,000 permutations — so omitting them can no longer pass unnoticed, and both prose graders now require all four sections of the return contract to be present.
- The gate-case contract is stated precisely in the eval docs: no value may be classified as match or mismatch after a failed gate; a blanket unverifiable naming the missing input is the correct outcome (what the live run produced, and what the grader accepts).
- Prose verdict-classification is retired from the keyword grader after a second live run broke it a second way (verdict-grouped tables whose rows carry no verdict word, on top of the earlier cross-value discussion lines). Verdicts are graded exactly on the machine-readable companion — including the conditional fields, which must sit on the record carrying each value — and the prose grader holds reports to structure, target coverage, and the boundary disclosure. All three artifacts of the second live run grade PASS under the split.
- A second review round tightened the JSON grader further, each finding verified against live output first: top-level provenance must be non-empty, not merely present; every record covering a target must itself be coherent (a correct sibling no longer excuses an unverified duplicate); the predicate must be stated on predicate records, not only tolerances on point records; and a record covering no in-scope manuscript value fails the report — which required completing the answer key with the 20-and-20 group split, now also emitted by the fixture pipeline as `n_experienced`/`n_inexperienced` instead of forcing agents to side-count it. The subagent wrapper sets `omitClaudeMd` so a manuscript repository's own instruction files are the skill's read-only input rather than the isolated agent's startup context. The gate-case companion contract is made explicit in `references/verification-report.md`: optional after a failed gate — the two live gate runs split on writing one — but held to all-unverifiable-with-reasons when written, and graded so by `run_agent_eval.sh`.
- A third round closed the gaps the second one opened or exposed. `plugin.json` registers the root skill explicitly (`"skills": "."`), without which the plugin shipped the agent but not the protocol it preloads. A bundled `computed` list is validated element by element against the answer key's documented values (`bundle_allowed`), so `[20, 999]` can no longer ride in on one correct member; a written gate companion must cover every in-scope target, not merely contain valid records; and the manual-fallback instructions in `run_agent_eval.sh` grade the JSON companion like the automatic branch. Two protocol contradictions of this release's own making are reconciled: the integrity norm now reads that verification writes nothing *of the author's* — only its marker and companion in the proposal directory — and the fixture pipeline takes an optional output directory (documented in its manuscript), giving a strict verification agent the read-only path that step 4's stop-and-ask rule asks for instead of forcing a judgment call the two live agents each resolved differently.
- A fourth round, same pattern of residual holes: the hook rejects a proposal directory that equals or contains the project (`FACTS_AND_FIGURES_OUT=..` would have whitelisted the whole tree; a self-test covers it); a boundary target's tie must be flagged on every covering record, not excused by one truthful sibling; producing commands must at least invoke the fixture's runtime — configured as `producing_command_must_contain` in the answer key rather than a verbatim match, since legitimate supplementary logged commands (the live agents' group-count cross-check) are protocol-sanctioned; and the subagent wrapper reads only the `<paper_context>` block from the manuscript's instruction files, ignoring the rest entirely instead of treating it as context.
- A fifth round: scratch roots must be fully disjoint from the project (a `TMPDIR` pointed inside it would have whitelisted author files — self-tested), and record pairing uses the `reported` field only, since the schema requires the manuscript value there verbatim and the free-text fallback let a record pair on a note mention while asserting a different value. Declined with reasoning on the thread: semantic validation of the free-text `tolerance` field — the grader never trusts it (classifications are independently recomputed against the answer key), and policing its prose would need either a fragile parser or a late schema restructure.
- A sixth round: required record fields must be non-empty, not merely present; the group-split bundle must carry both group counts (`bundle_expect`), so `[20]` cannot verify the 20-and-20 claim; the gate branch rejects stray records like the normal branch; the boundary tie must be raised in Author decisions specifically, where the protocol puts the rounding-convention choice, not merely mentioned in Results; and the subagent wrapper's failed-gate adaptation returns the complete four-section contract rather than stopping after the first section. Declined with reasoning: string-inspecting producing commands beyond the runtime-token tripwire (provenance is verified by re-execution or not at all, and the live agents' legitimate supplementary one-liners make script-name matching a false-failure machine), and exact-decimal endpoint arithmetic in the fixture self-check (the design doctrine, now stated in its docstring, is that planted values are constructed exactly and never sit within float noise of an endpoint they do not lie on).
- A seventh round, all six adopted — each a real shell or CI bug, or a cheap behavioral check of the skill's actual promises. The eval harness now verifies conduct, not just reports: after each run the workspace must be untouched outside the proposal directory (file hashes compared, so a pipeline run that writes `results/` into the manuscript tree fails) and the run marker must be gone. Unverifiable reasons must name the missing source (`reason_must_contain`); a failed-gate companion may not assert boundary ties. Two latent bugs in copyable snippets: the plain-skill hook registration now quotes `$CLAUDE_PROJECT_DIR` (a checkout path with spaces silently disabled the guard), and the README CI template sets `shell: bash` so `pipefail` propagates a failing `claude` exit through `tee`.
- An eighth round. The important one cut the other way: the stray-record check would have failed an agent *more* thorough than the answer key, since the manuscript's 0–100 scoring scale and three-month interval are not keyed — `out_of_scope_anchors` now exempts records covering them. Also: `computed` must be explicitly null on unverifiable records, not merely absent, so the companion keeps a stable shape for consumers; the four sections must appear as actual headings, not merely be mentioned in a sentence; and the wrapper's final-message rule states its one exception (the ambiguous-request clarification return), resolving a contradiction between two of its own adaptations. Declined as already-open families: compound `reported` strings, and scanning prose for global verdict sentences after a failed gate.
- A ninth round, all four adopted. The run marker's contract is reworked so the hook needs no environment coordination: the marker always lives at `facts-and-figures-out/.active`, and when the author named a different proposal directory its path is the marker's single line, which the hook reads — previously a custom directory chosen mid-session left the guard silently unarmed. The JSON grader verifies that `data_versions` carries the actual fixture digest, computed from the repository's own data file; the fixture self-check confirms each keyed value still appears in the manuscript, so a stale answer key cannot bless a drifted manuscript; and `run_agent_eval.sh --grade-only` applies the identical grading and workspace-integrity suite to manually run workspaces.
- A tenth round, six adopted — half of them consequences of the ninth round's own marker rework, which is how adversarial review should work. Parallelism is now honestly scoped to separate checkouts (the singleton marker is the coordination point, so per-run proposal directories no longer help); under a custom proposal directory only the marker file itself stays writable in the default directory, so generated work cannot land outside the directory the author chose; integrity snapshots include `.claude`, so a run that tampers with its own guard or the installed skill fails; `manuscript_files` must name the scoped manuscript; CI's version check uses fixed-string matching (regex dots accepted `0x5y0` as `0.5.0`); and the protocol states that an input the pipeline itself treats as optional fails only its values, not the whole gate — the ambiguity both live agents happened to resolve correctly but a literal reading could not. Declined: constraining out-of-scope exempt records to unverifiable, which would false-fail a legitimate bounds-predicate verification of the 0–100 scale — records outside the answer key are outside its guarantees by construction.
- An eleventh round, all four adopted. The hook judges a path addressed inside the repository as addressed: a symlink in the tree leading into `/tmp` no longer routes author-data writes into the scratch exemption (self-tested). Integrity snapshots record every entry's type and symlink target, so planted symlinks, FIFOs, and directories fail the workspace check, not only regular files. The hook self-test parses the actual decision shape (`hookSpecificOutput.permissionDecision == "deny"`) instead of substring-matching the word deny. And `plugin.json` uses the backward-compatible `"./"` root-skills path.
- A twelfth round, all three adopted: the hook also requires a write addressed inside the proposal directory to *resolve* inside it, closing the inverse of the previous symlink escape (`facts-and-figures-out/escape -> ../manuscript.md`; eighteen self-test cases now); the top-level `pipeline_command` must invoke the canonical pipeline script, with output-directory arguments still legitimate; and the fixture self-check validates every bundled group count via `also_check`, so `n_inexperienced` drift fails the deterministic layer too.
- A thirteenth round, three adopted, two declined into their open canonical threads. The marker lifecycle exemption applies only when the marker is a regular file — `resolved == realpath(marker)` was a tautology that let a marker replaced by a symlink to an author file be overwritten through its own exemption (nineteen hook self-test cases). The gate graders gain deliberately invalid fixtures, so a grader reduced to unconditional success fails its own self-test. Record locations must name a manuscript place (a filler string cannot support the value-by-value review). Declined: a per-occurrence manuscript-number inventory (the completeness spiral) and parsing `pipeline_command` to prove execution (the provenance family — string inspection cannot prove a command ran; re-execution remains the roadmap answer).
- A fourteenth round, one adopted: integrity snapshots record permission modes, so a run that chmods an author file — making the paper or its pipeline unusable without changing a byte — fails the workspace check behaviorally.
- A fifteenth round, five adopted, one split. The hook closes two more symlink escapes: the proposal root must resolve to its own lexical path, since a `facts-and-figures-out` symlinked at `data/` would have laundered every generated file into the author directory it points at; and a marker that is a broken symlink still arms the guard — `exists()` read a dangling link as absent, leaving the hook inert exactly when a write recreating the marker would follow the link to create an author file (twenty-four self-test cases now). The eval and the README CI template set `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, keeping `ANTHROPIC_API_KEY` out of the Bash commands those workflows pre-approve — the variable was verified against the Claude Code documentation before adoption. Workspace snapshots are reimplemented in Python (`evals/snapshot_workspace.py`, byte-identical output) because GNU `find -printf` and `sha256sum` are missing from stock macOS; and the headless eval closes off `evals/` entirely while the measured agent runs, since excluding the answer key from the workspaces did not stop a Bash-approved process from reading it out of the checkout. The split: `reported` must be a string on every record — the schema demands the manuscript text verbatim, and a JSON `10000` graded PASS where the manuscript says `10,000` — while validating its content against per-target verbatim keys stays declined in the typed-fields thread as the same answer-key-expansion spiral as the tolerance-string family.
- A sixteenth round, all seven adopted. The hook rejects writes through hard links — the inode route the symlink checks cannot see: a proposal file (or the marker) hard-linked to the manuscript keeps its realpath under the proposal while a write through it would truncate the manuscript, so any multiply-linked regular file is denied (twenty-six self-test cases). The CI templates drop checkout credentials before granting Bash: `persist-credentials: false` and `permissions: contents: read` in both the paper-repo template and `agent-eval.yml`, since checkout persists a pushable token in `.git/config` by default. The manual-eval instructions carry `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` in the printed commands themselves — the script's own export dies with it. The answer-key lockout extends to the git object database (`git show HEAD:evals/expected.json` read past the working-tree chmod). `workspace_clean` tests `-L` as well as `-e`, since a marker left as a dangling symlink still arms the hook but read as removed. The gate grader rejects a digest asserted for the removed input (provenance must record absence; a fabricated `sha256:000…` graded PASS). `skill_version` must equal the installed `VERSION` — the static mocks now pin it at self-test time so a release bump cannot break fixtures that test report semantics, not release arithmetic. And `agent-eval.yml`'s paths filter includes the workflow file itself, so orchestration-only fixes still exercise the run they orchestrate.
- A seventeenth round, four adopted, two declined. The hook guards the marker bootstrap — the one write the protocol makes while unarmed: creating `.active` through a default directory that is already a symlink would land the marker in an author directory before the guard exists, so that write must resolve to the marker path even when no marker does (twenty-nine self-test cases). The gate grader requires `data_versions` to record the removed input as explicitly absent, as the schema mandates — "present and verified" is not a recorded absence — and the verify grader locates the hashed input by normalized path, since the schema requires the actual path, not one dictionary spelling (`./data/workers.csv` and an absolute workspace path are legitimate). `agent-eval.yml` uploads the gate companion alongside the verify one, so a gate-side JSON failure is inspectable without an API-backed rerun. Declined: rejecting report-wide verdict sentences in gate prose (the round-8 decline re-raised — prose verdict-scanning is the retired false-failure machine, and negations like "no value may be classified as match" are exactly what such a scanner trips on; the JSON companion is the verdict channel), and replacing the answer-key lockout with a filesystem sandbox (mode bits are owner-reversible, which the harness now documents as a known limit: the lockout is hygiene against incidental reads by an honest agent, and a process-level guarantee is CI-infrastructure territory).
- An eighteenth round, five adopted, with the important one a redesign rather than the suggested restriction. The armed run marker is now read-only to guarded tools: a mid-run rewrite would re-aim the write boundary itself (name `data` as the proposal directory, then edit the dataset through the very tools the hook guards), so the custom proposal directory is named at creation — the bootstrap write the unarmed branch validates — and never after; the author-named root itself stays honored, because the author's naming is the protocol's documented input (thirty self-test cases). `SKILL.md`'s entry-point gate is qualified to required inputs, resolving its contradiction with the optional-input rule the protocol gained in round ten — an agent loading only the entry point could legitimately have stopped the whole verification over the fixture's optional wave-2 file. Integrity snapshots prune only a *real* proposal directory, so a run that replaces the root with a symlink and routes generated work outside it fails the workspace check (verified by hand). The boundary disclosure must sit with the affected value in Author decisions — "no boundary concerns for the overall mean 71.48" satisfied the old word-anywhere check, and anchoring defeats that exact misdirection without the negation parser that stays declined. And the gate grader requires distinct records to cover the targets, since after a failed gate all records share one classification and one record concatenating every anchor satisfied all ten coverage checks at once.
- A nineteenth round, all six adopted, two of them against live evidence checked first. The gate cardinality check becomes a bipartite matching — a merged record padded with duplicates of one target inflated the record count past the previous threshold, so now every target must claim a distinct record of its own. Integrity snapshots record regular files' link counts: replacing an author file with a hard link to a byte-identical copy under the pruned proposal directory left content, mode, and hash unchanged, and only the raised link count betrays the shared inode (verified by hand). A scalar `computed` is rejected for bundled claims — `20` slipped past `bundle_expect` into the scalar path and verified half of the 20-and-20 split. The prose grader requires each mismatch and unverifiable target to surface in Author decisions, which the live runs all did unprompted (the mock had omitted them and is completed). The eval restores each locked directory's own prior mode instead of forcing 755 onto a private checkout, and the manual-fallback commands quote their paths so a workdir with spaces works.
- A twentieth round, five adopted, two declined as re-raises. The hook reads the marker only when it is a regular file: a FIFO planted at the marker path armed the guard and then blocked `open()` waiting for a writer, hanging every guarded write — worse than either allowing or denying (the self-test runner now carries a hard timeout so a blocking regression fails loudly; thirty-two cases). The answer key's gate absence check loses the term "gate", which the mandatory Scope and gate heading auto-satisfied — a gate report claiming the dataset was available graded PASS. Gate records must each cover exactly one target (ten copies of a concatenated record formed a perfect matching). Schema shape now holds for every record, in or out of the key's scope: an exempt record is exempt from value equality, not from the classification enum or its conditional fields. And `environment` must name the interpreter with the documented seed appearing in the provenance — "unknown" supported no reproduction. Declined: validating `reported` against keyed verbatim manuscript text (the typed-fields thread's standing answer-key-expansion spiral), and per-occurrence manuscript drift tracking in the fixture self-check (the completeness-spiral family — the fixture is synthetic and version-controlled, and an edit to it lands in diff review, not past the answer key).
- A twenty-first round, two adopted, two declined as the canonical threads re-raised. The hook drops its scratch allowance entirely: the protocol authors new files only in the proposal directory, shell-level temp files were never intercepted anyway, and a pipeline input that happens to live under `/tmp` is still an author file a disjoint scratch root would have whitelisted — guarded writes now land in the proposal directory or nowhere, which also collapses the two allowance branches into one resolved-path rule. Record locations must name a section-level place (`abstract`, `data`, `results`, a table or figure): the bare word `manuscript` locates nothing in a document that repeats numbers across sections — calibrated against live output, which legitimately located a second occurrence of the group split in a section the key does not name, so the keyed section itself is deliberately not required. Declined into their canonical threads: semantic validation of the free-text `tolerance` field (the grader recomputes every classification from the answer key and never trusts the field) and producing-command string inspection beyond the runtime-token tripwire (string matching cannot prove a command ran; re-execution remains the roadmap answer).
- A twenty-second round, all four adopted. The hook trusts marker content only from a plain, singly linked regular file at the marker path itself (`lstat`, not `stat`): a marker symlinked or hard-linked to a file whose first line names `data` would otherwise have re-aimed the proposal root at the dataset — the content-read hole left after the marker-path writes themselves were locked down (thirty-four self-test cases). `SKILL.md`'s companion mandate gains the failed-gate exception the schema reference already carried, resolving the entry point contradicting its own reference. The global shape check requires `tolerance` and `producing_command` on every match or mismatch record, exempt or not — an out-of-scope record could previously assert an unverified match with no provenance at all. And the gate absence entry is located by normalized path like the normal-case check, since the basename substring accepted an absence recorded for `data/notworkers.csv`.
- A twenty-third round, two adopted, one reworded, one declined on checked evidence. The armed marker is read-only on the resolved path too: an alias symlink planted in the proposal directory (`alias -> .active`) skipped the lexical marker check while resolving to the marker itself, re-aiming the boundary through the one file the proposal allowance would bless (thirty-five self-test cases). The eval harness refuses a populated workdir it did not create — `run_agent_eval.sh .` would have recursively removed `verify/` and `gated/` from the current project; a sentinel file marks harness-owned directories, and anything else non-empty is refused intact. The paper-repo template's scrub comment now states the mechanism's limit honestly: environment scrubbing is hygiene against accidental reads, not isolation — a hostile same-user process can read a parent's environment via `/proc`, and a pipeline the author does not trust belongs in a container or separate user (the container itself stays out of a README template, consistent with the documented-limit position on the answer-key lockout). Declined with evidence: excluding the fixture README as a disclosed answer table — the file at the reviewed commit is a three-sentence synthetic-fixture notice with no values in it, and the actual answer table lives in `evals/README.md`, which the workspaces never receive and the run-time lockout covers.
- A twenty-fourth round, all four adopted — one of them a leniency fix in the eval's favor. Negated verdict sentences in gate prose ("unverifiable, not a match or mismatch", phrasing a live run produced) are stripped before the one remaining verdict scan classifies, so gate-compliant reports stop false-failing while a positive assertion still fails (a want-0 self-test locks the leniency). The gate's absence language must co-occur with the removed input — "workers.csv is available" plus "wave2_followup.csv is missing" passed on two independent substring hits. The environment must name a *versioned* interpreter and the seed must sit in a provenance field (environment, pipeline command, producing commands, or a bundled computed value), not in a note. And the answer-key lockout resolves the real git directories via `rev-parse` — in a linked worktree `.git` is a pointer file the old directory test skipped entirely, leaving `git show` a path to the key through the main checkout; parent directories are restored before children so the unlock order is valid.
- A twenty-fifth round, all three adopted. The marker bootstrap guard covers both spellings: a write addressed straight at the redirect target a symlinked `facts-and-figures-out` resolves to (`data/.active`) bypassed the lexical-only check and would have created the canonical marker through the symlink (thirty-six self-test cases). The paper-repo template captures prose under `$RUNNER_TEMP` instead of the checkout root, where `tee verification-report.md` was a shell write past the hook that would truncate an author file of that name. And the template's CI gate rejects an empty `values` array — a report that verified nothing exited green — printing checked/flagged counts, with the honest note that completeness beyond non-emptiness is the author's spot check, since a real paper has no answer key.

### Added

## [0.3.0] - 2026-10-07

Adds an execution form and a mechanical guard around the existing protocol without moving the protocol itself: `SKILL.md` and `references/` remain the single source of truth, and the new files point at them rather than restating them. Minor bump per the release rule — the run marker is a new observable step in the gate, and two new install surfaces exist.

### Added

- `agents/claude-code/facts-and-figures.md`, a subagent wrapper that runs the protocol in an isolated context. Isolation is an integrity feature, not hygiene: the run receives only the pinned request, never the surrounding conversation where the author may have said what they hope the numbers show — the contamination the no-forking-paths rule exists to prevent. The wrapper locates the installed skill, reads `SKILL.md`, and adds only the agent-mode adaptations: a mid-run question becomes an early return, a failed gate is an early return, outcome-predicting framing in the request is ignored and disclosed, and the final message is exactly the four-section contract. Fail-open by design, and documented as a guardrail rather than a sandbox: shell-level writes are not intercepted, and the master rule remains the primary control. Registration instructions live in `README.md`.

## [0.2.0] - 2026-08-15

Makes the skill self-contained. Extracted from `blue-pencil`, it carried citations to reference files that did not come with it: figure regeneration pointed at `blue-pencil`'s `edit-checks.md` for its design guidance, and the protocol appealed to a master rule the standalone `SKILL.md` never stated. Both are now resolved inside this repository, and the skill gains the two things the extraction dropped that it actually needed: the manuscript-context step and an explicit account of where the analysis runs.

### Added

- `references/figure-design.md`, replacing the inherited dependency on `blue-pencil`'s `edit-checks.md`. It states the figures-as-primary-text standard, an explicit two-column split of what a re-render may change (color, ordering, labeling, scale formatting) against what it may not (data path, sample, transformations, estimates, added smoothing, truncated axes), an ordered presentation-improvement procedure, and the value-parity confirmation a re-render must pass before being proposed.
- `references/compute-environment.md`. Local-first execution with a measure-before-you-move rule; detection of credentials `cloud-bootstrap` has already placed in the repository (`.cloud-config.json`, `.cloud-credentials.<email>.enc`, `*_CREDENTIALS_KEY`) with a table distinguishing the four states, three of which are not "the cloud is available"; four gates before a remote run (author consent, a destination the project already uses, bounded cost, preserved reproducibility); and the extra provenance a remote run carries — environment and image digest, region and job ID, a pinned data snapshot, seeds and reduction order. Credential creation, rotation, and IAM stay with `cloud-bootstrap`.
- `SKILL.md` states the master rule (never assert unverified substance) and its two corollaries directly, so `references/analysis-integrity.md`'s appeal to it resolves.
- `SKILL.md` gains "Load the manuscript context" (the `<paper_context>` block in the manuscript repository's `AGENTS.md`, `CLAUDE.md`, or `paper-meta.md`, plus the include-graph rule for choosing the manuscript file set) and "Choose where the analysis runs".
- `AGENTS.md` for this repository, carrying the precedence rule that separates it from the manuscript repository's `AGENTS.md`: this file governs the skill's own directory, the manuscript's is read-only input, and installing the skill never writes one next to an author's paper. It also carries the repository layout, the editing invariants, and a shell one-liner that fails on a dangling `references/` citation.
- "Establish the manuscript context" in `references/analysis-integrity.md`, which owns the context-block lookup, the read-only rule for the manuscript's own context files, and the include-graph rule for choosing the manuscript file set. `SKILL.md` carries only the trigger and the pointer, so the always-loaded entry point stays thin and the protocol has a single owner.
- A rounding-tolerance rule in verification step 5: state the tolerance before comparing, set it from the manuscript's own reported precision, and never widen it to convert a mismatch into a match. Values the manuscript states as bounds (`p < 0.001`, ranges, floors and ceilings) are checked as predicates fixed before the comparison rather than by equality, so a pipeline value that satisfies the reported bound is a match rather than a spurious mismatch.
- A row in the credential-state table for a repository configured for the cloud but carrying no credentials file for the current user (a fresh clone, or a collaborator not yet provisioned), which is `cloud-bootstrap`'s add-team-member case; plus the rule that providers are read independently and that any other partial configuration resolves as unavailable.
- Environment capture (interpreter and package versions, seeds) in verification step 4 and in the provenance norm, for local runs as well as remote ones.
- `VERSION`, `CHANGELOG.md`, and a `.gitignore` for the proposal directory.

### Changed

- Every logged command is recorded with its secrets redacted and their variable names kept. A pipeline invoked with a connection string, signed URL, API key, or token would otherwise have that secret copied verbatim into the report by the very rule requiring the exact command; the same applies to environment-capture output and to a leaked credential, which is named as needing rotation. Local runs are covered, not only remote ones.
- A run that provisions anything records the teardown command and each resource's final observed state. "Never leave a machine running" was unverifiable from the report, so a silently failed cleanup could keep charging the author while the output looked compliant.
- The rounding tolerance is a half-open interval, `m - u/2 <= v < m + u/2` with `u = 10^-k`, exactly the values that display as the reported number under round-half-up. The previous closed interval accepted the upper endpoint, so `1.255` would have been certified as matching a reported `1.25` even though both half-up and half-even display it as `1.26`. Endpoint hits are reported as boundary cases in `Author decisions` rather than resolved silently, since half-even — the default in most numerical libraries — disagrees there.
- The frontmatter description asks for reachable, pipeline-defined data rather than data stored in the repository, matching the gate. A host selecting skills from the description alone would otherwise decline to load the skill for a warehouse-backed project the gate now admits.
- Capability 2 in the protocol recognizes the gated uncertainty variant that `references/figure-design.md` introduces, and its parity check treats the variant's added marks as disclosed additions rather than parity failures. The protocol had continued to route any absent series to capability 3 unconditionally, contradicting the reference.
- The gate condition asks for the author's analysis code plus data reachable as the pipeline itself defines it, rather than data residing in the repository. A project whose pipeline is configured to read a warehouse table or a bucket object was previously gated out of verification entirely, despite `references/compute-environment.md` existing to support exactly that case. Configured but unreachable remains a gate failure, and substituting another source is never the remedy.
- Measurement happens after the plan is pinned and stays blind to values. Timing a pipeline means running it, so a subset run taken before the number inventory or the specification was fixed could surface a result and shape the plan that follows — the forking-paths failure this skill exists to prevent, arriving through the back door of a profiling step. Preferred paths are those that cannot produce a reported quantity (dry runs, plan modes, a load stage with the analysis stopped), and a value that lands in front of you anyway is disclosed rather than ignored.
- The rounding tolerance fixes its tie convention: a value matches when `|v - m| <= 0.5 x 10^-k` at the manuscript's reported precision, a closed interval, so an exact tie is a match under either half-up or half-even rather than depending on which convention the run happened to assume.
- `cloud-bootstrap` is named as an optional runtime prerequisite in `references/compute-environment.md` and `README.md`: everything local works without it, and it is the only sanctioned path from an encrypted credentials file to an activated session. A fully configured repository without it means remote execution is unavailable, not that credentials get decrypted by hand.
- The master rule defines verified substance by logged execution and traced inputs rather than by who authored the producing code. The earlier wording ("the author's own data and code") would have forbidden reporting results from the new scripts capabilities 2 and 3 exist to write, since it outranks every capability instruction. Run metadata is named as provenance, not substance.
- Plotting uncertainty the pipeline already computed is no longer classified as presentation. It adds marks the original lacked and changes what the reader concludes, so it is now the capability's one permitted addition, gated: proposed as a labeled variant beside the faithful re-render and named in `Author decisions` as an addition.
- Deterministic reduction is mandatory where the pipeline offers one; where it does not, the run says so and any value that moves between runs is classified unverifiable rather than matched. "Prefer" left the choice unobservable in the report.
- A cost that cannot be bounded is a stop rather than a question: approval does not convert an unknown cost into a known one, so the run needs a dry-run estimate, a documented rate against a known input size, or an enforceable ceiling.
- Remote outputs go to a proposal prefix inside a location the project already uses. The earlier wording let the author name a new remote dataset, which the second gate forbids creating; a new destination is now something the author creates before the run, not something a run creates.
- Generated work stays in the proposal directory unconditionally. The earlier "unless the author explicitly chooses to adopt them" let a run place files into the author's tracked code or manuscript, against the norm that a proposal is adopted only when the author moves it in.
- Renamed the skill from `paper-analyst` to `facts-and-figures`: `SKILL.md` frontmatter, `README.md`, `agents/openai.yaml`, and the default proposal directory, now `facts-and-figures-out/`.
- `references/analysis-integrity.md` drops the "lane" framing inherited from `blue-pencil`, where it named one branch of a larger editorial skill, and refers to the skill directly.
